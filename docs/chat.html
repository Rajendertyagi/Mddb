Does MDDB support PDF upload?
Yes! MDDB supports uploading PDF, DOCX, ODT, RTF, LaTeX, YAML, HTML, TXT, and Markdown files. All formats are auto-converted to Markdown on ingest.
How do I set up vector search?
Set the MDDB_EMBEDDING_PROVIDER env variable (e.g. "openai" or "ollama"), provide your API key, and MDDB will auto-embed documents on ingest. Then use POST /v1/vector-search to query.

Architecture

Three components work together: the widget (client-side), the chat server (Rust), and MDDB (knowledge base).

[Your Website] [MDDB Infrastructure] | | <script> | mddb-chat.min.js +----------+ | | mddbd | | WebSocket | :11024 | v | gRPC | +-----------+ gRPC +----^-----+ | mddb-chat |--------------------+ | :11030 | | (Rust) |---- HTTP ---> LLM Provider +-----------+ (OpenAI / Claude / Ollama / Bielik / ...)
🎨

mddb-chat-widget

TypeScript IIFE bundle. Shadow DOM isolation, localStorage session persistence, markdown rendering, feedback ratings. One script tag to deploy.

🦀

mddb-chat

Rust/Axum WebSocket server. Agentic tool-calling loop (max 5 rounds), session management, rate limiting, webhook dispatch. Connects to MDDB via gRPC.

📝

mddbd

MDDB knowledge base. Hybrid search (BM25 + vector), full-text search, document storage. The chat server queries it for RAG context.

How It Works

User asks a question, the server searches your docs, then the LLM answers based on what it found.

1

User Message

User types a question in the chat widget. Sent via WebSocket to mddb-chat server.

2

RAG Search

LLM calls search_docs tool. Server queries MDDB via gRPC (hybrid/vector/FTS search).

3

LLM Response

Search results + conversation history sent to LLM. Response is streamed back in real-time.

4

Streaming

Chunks arrive via WebSocket. Widget renders markdown in real-time with typing animation.

Features

Everything you need for a production AI chatbot, built-in.

🔍

RAG-Powered Answers

Agentic tool-calling loop. LLM searches your MDDB docs before answering. Up to 5 search rounds per question.

⚡

WebSocket Streaming

Real-time token streaming. Responses appear character-by-character with typing indicator animation.

🎯

Scenarios

Define multiple chat personas with custom system prompts, allowed collections, temperature, and max turns.

🔒

Session Management

Concurrent user limits with queue. Session TTL (configurable, default 24h). localStorage persistence across reloads.

🛡️

Rate Limiting

Per-IP token bucket rate limiting. Input sanitization, max message length, response length caps.

👍

Feedback Ratings

Thumbs up/down on every response. Negative feedback logs full Q&A pairs for analysis and improvement.

🔔

Webhooks

Events: session.start, session.end, queue.full. Async dispatch with retry. HMAC-SHA256 signatures.

🎨

Shadow DOM Widget

Fully isolated from host page styles. Configurable via data-* attributes. Mobile-responsive. < 30KB gzipped.

📝

Markdown Rendering

Bot responses render bold, italic, code blocks, links, and lists. Clean text from stripped markdown search results.

Quick Setup

Three steps to deploy AI chat on your website.

1. Start the services

bash — docker compose 
# Clone and start all services
git clone https://github.com/tradik/mddb.git && cd mddb

# Set your LLM API key
export MDDB_CHAT_LLM_API_KEY="sk-your-key-here"

# Start MDDB + Chat Server + Widget
docker compose -f docker-compose.dev.yml up -d mddbd mddb-chat mddb-chat-widget

# Services available:
#   mddbd:              http://localhost:11023 (HTTP), localhost:11024 (gRPC)
#   mddb-chat:          ws://localhost:11030/ws (WebSocket)
#   mddb-chat-widget:   http://localhost:11032 (static JS bundle)

2. Load your docs into MDDB

bash — load documents 
# Add documents to your "docs" collection
curl -X POST http://localhost:11023/v1/add \
  -H "Content-Type: application/json" \
  -d '{"collection":"docs","key":"getting-started","lang":"en",
       "contentMd":"# Getting Started\n\nWelcome to our product..."}'

# Or upload files directly (PDF, DOCX, ODT, etc.)
curl -X POST http://localhost:11023/v1/upload \
  -F "file=@documentation.pdf" \
  -F "collection=docs" -F "key=docs-pdf" -F "lang=en"

# Reindex vectors for semantic search
curl -X POST http://localhost:11023/v1/vector-reindex \
  -d '{"collection":"docs"}'

3. Embed the widget

html — your website 
<!-- Add this single script tag before </body> -->
<script src="https://your-cdn.com/mddb-chat.min.js"
  data-server="wss://chat.example.com"
  data-scenario="assistant"
  data-theme="light"
  data-accent="#3B82F6"
  data-position="bottom-right"
  data-session-ttl="24">
</script>

Configuration

Server config via TOML. Widget config via HTML attributes.

🦀 Server — config.toml

[server]
host = "0.0.0.0"
port = 11030
cors_origins = ["*"]

[mddb]
grpc_addr = "http://mddbd:11024"
default_collection = "docs"
search_top_k = 3
search_type = "hybrid"  # hybrid, vector, fts

[llm]
provider = "anthropic"  # or "openai"
api_url = "https://api.anthropic.com/v1"
api_key = ""  # or env MDDB_CHAT_LLM_API_KEY
model = "claude-sonnet-4-20250514"
max_tokens = 1024
temperature = 0.7

[session]
max_concurrent = 2
queue_size = 10
session_ttl_minutes = 1440  # 24h
max_history_length = 50
max_response_length = 4096

[security]
rate_limit_per_minute = 30
max_message_length = 2000

[scenarios.assistant]
name = "Documentation Assistant"
system_prompt = """You are a helpful assistant.
Answer based on the provided context."""
allowed_collections = ["docs"]

WebSocket Protocol

📤 Client → Server

// Join session
{"type":"join","name":"Jan","scenario":"assistant"}

// Send message
{"type":"message","content":"How do I upload PDFs?"}

// Resume existing session
{"type":"resume","session_id":"uuid-here"}

// Rate a response
{"type":"feedback","rating":"down",
 "question":"...","answer":"..."}

// End session
{"type":"end"}

// Keep-alive
{"type":"ping"}

📥 Server → Client

// Session started
{"type":"session","id":"uuid","scenario":"assistant"}

// In queue
{"type":"queued","position":3}

// Streaming response (many of these)
{"type":"chunk","content":"MDDB supports..."}

// Response complete
{"type":"done"}

// Session ended
{"type":"ended"}

// Error
{"type":"error","message":"rate limited"}

// Keep-alive reply
{"type":"pong"}
